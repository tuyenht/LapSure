# LapSure UI Rule

Recommended activation: **Always On** for UI/product work.

Read:
@../../docs/ui/LAPSURE_UI_MASTER_SPEC.md
@../../docs/ui/ANTIGRAVITY_IMPLEMENTATION_CONTRACT.md
@../../docs/ui/references/README.md

Use `../../docs/ui/references/CONTACT_SHEET.jpg` and the approved visual pack as visual-language references after the product/spec contracts.

UI goals:
- A first-time user understands current state, issue and next action without reading documentation.
- Use grouped navigation and progressive disclosure.
- One clear primary action per workflow screen.
- Vietnamese-first copy.
- All statuses use icon/text, not color alone.
- Preserve explicit uncertainty states.
- Do not show a generic machine health percentage unless the underlying metric is real and clearly named.
- Mockups are visual direction only and never authorize fake data.
- Screen contracts and evidence semantics override pixel fidelity.
- Never use archived visual concepts unless explicitly requested.
- Prefer reusable native components/tokens and DPI-aware layout.
- Keep technical raw evidence accessible but secondary to guided UX.
